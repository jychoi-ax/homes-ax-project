# AX project version 0.1

## 1. 자동화 vs AX

### 1) 왜 구분이 필요한가

- 사내에서 `자동화`와 `AX`를 같은 말로 쓰는 경우가 많아, 목표/우선순위 설정이 어렵다.
- 이번 프로젝트에서 추구하는 것이 **단순 자동화**인지, **AX(에이전트 기반 업무 수행)**인지 선택해야 한다.

### 2) 자동화(Automation)란?

- 사람이 하던 **반복·정형 업무를 규칙 기반으로 대체**하는 것.
- 구현 방식은 자유롭다: Script, RPA, 워크플로우 툴, 매크로 등 정해진 절차를 정해진 방식으로 실행.
- 특징: 입력/조건이 명확하고 예외가 적을수록 효과가 크며, 변경/예외가 많으면 유지보수 비용이 증가한다.

### 3) AX란?

- 목표는 `자동 실행`을 넘어, **AI Agent가 업무를 수행**하도록 만드는 것.
- 에이전트는 단일 규칙 실행이 아니라, 상황을 이해하고(컨텍스트), 도구를 호출하고(시스템/DB/API), 결과를 검증·수정하며(피드백), 다음 행동을 이어간다.
- 특징: 예외/비정형이 많은 업무에서도 확장 가능하지만, 데이터/도구/가드레일/평가 체계가 필요하다.

### 4) 한 줄 정리

- 자동화: **정해진 일을 빠르게** (규칙 실행)
- AX: **일을 대신하게** (에이전트가 목표 달성)

## 2. What?

이번 프로젝트에서 만들고자 하는 것은 아래 **4개 레이어**로 구성된 업무 시스템이다.

### 0) Layer0: Data Foundation

- 모든 데이터를 수집/정제/적재하는 **ETL 파이프라인 + 스토리지**
- 이를 운영·관제·품질관리하는 AI Agent: **Mycroft**

### 1) Layer1: Core Infra

- **IMS**: 투자개발/딜 소싱·검토·집행 관련 업무 인프라
- **PMS**: 임대 운영 인프라
- **CMS**: 고객/콘텐츠/커뮤니케이션 관리 인프라
- **HMS**: 사내 관리 인프라

### 2) Layer2: Apps

- AMS(업무 앱), 챗봇, 홈페이지 등

### 3) Layer3: Decision System

- 투자/운영/고객/조직 의사결정의 품질과 속도를 높이는 지원 시스템

## 3. Mind Map

- **Layer0 -> Layer1 -> Layer2 -> Layer3**로 갈수록 기반에서 사용자 가치와 의사결정으로 올라간다.
- 이 문서는 범위 정의와 확장 방향 합의를 위한 기준 문서다.

### Layer0: Data Foundation

- 단일 데이터 파이프라인, 스토리지, 권한, 로그가 전제다.
- **Mycroft**는 이 기반 위에서 데이터 신뢰도와 운영 관제를 담당한다.

### Layer1: Core Infra

- IMS / PMS / 사내시스템 / CMS가 Layer1의 도메인 인프라다.
- 각 도메인에는 담당자 역할에 대응하는 에이전트가 배치된다.
  - IMS: 사업성 검토 / 딜 소싱 / 투자자-매도인 조율 / Deal 구조화·설계
  - PMS: 입주민 관리 / 신규 고객 대응 / 재무 / 시설
  - 사내시스템: 내부 회의록 관리 / 내부 지식 Q&A 챗봇
  - CMS: 외부 소셜 채널 관리 / 마케팅
  - BMS: 매물 수집

### Layer2: Apps

- Layer2는 Layer1의 기능을 사용자에게 전달하는 접점이다.

### Layer3: Decision System

- 각 도메인의 결과와 지표를 요약, 비교, 시뮬레이션, 리스크 경고로 연결하는 지원 레이어다.

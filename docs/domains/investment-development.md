# 투자개발본부 AX 기획

## 투자개발본부 워크플로우 가설

투자개발본부 업무를 4단계로 나누어 볼 때, 각 단계에 맞는 agent가 필요하다.

| # | 단계 | 본질 | 담당 Agent |
|---|---|---|---|
| 1 | 소싱 | 채널(중개사, 증권사, 운용사, 지인) 유입 + 직접 발굴(건축대장, 인허가) | 소싱 Agent (AMS 앞단) |
| 2 | 검토 | 등록된 자산의 깊이 있는 검토 + 이력 관리 | 검토 Agent (AMS 본체) |
| 3 | 조율 | 매도인 달래고 + 투자자 안심시켜 딜 성사 속도 ↑ | 조율 Agent |
| 4 | 구조화 | 딜 속도 vs 자금 속도 시차 메우기 (Plan A→B→C) | 구조화 Agent |

## 확인 부탁드리는 질문

**Q1.** 위 4단계 설정(소싱/검토/조율/구조화) + 단계별 역할 분담(4개 Agent) 구조가 맞다고 보시나요? 다르게 묶거나 이름 바꿔야 할 부분 있을까요?

**Q2.** AMS(검토 agent)가 검토 과정에서 답해주면 좋을 질문이 있다면? (예: "비슷한 조건 과거 딜은 어떻게 되었나?", "이 가정값이 합리적인가?", "이 입지에서 우리가 놓치고 있는 risk는 무엇인가?")

**Q3.** 3·4단계(조율·구조화) 두 agent의 기능 피드백 및 개선 요구 사항?

**Q4.** AMS 말고도 AX 본부가 만들어주면 좋을 시스템·기능·서비스?

**Q5.** 딜 1건 검토에 가장 시간이 많이 걸리는 작업 Top 3?

**Q6.** 지금 안 보고 있는데 봐야 하는 데이터/관점 1가지?

**Q7.** 만능 AI agent가 있다는 가정에서 가장 시간을 아껴줄 수 있는 작업 Top 3?

## 1단계 — 소싱 Agent (AMS 앞단)

**가설**: 투자개발본부의 소싱 업무에서 (1) 다양한 채널로부터 들어오는 매물 정보를 정리·관리하는 일과 (2) 건축대장·인허가 등 공공 데이터로 자체 발굴하는 일이 시간을 많이 소모하고 있다. 이 구간의 반복 업무를 자동화하면, 동일 인력으로 더 많은 후보를 커버하고 검토 속도를 높일 수 있다.

→ 따라서 **AMS 앞에 소싱 Agent를 두고, AMS는 정리된 매물만 받도록** 역할 분리 제안.

**기능 후보:**

- **입력/정리(채널 유입 매물)**
  - 채널(중개사·증권사·운용사·지인) 유입 매물 데이터 입력기 역할
- **외부 데이터 수집/정리**
  - 외부 채널(네이버·온비드·디스코) 자동 수집·정리
  - 건축대장·인허가 정보 자동 수집·정리
- **1차 스크리닝(개략 검토) 자동화**
  - 개략 검토 로직을 투자개발본부로부터 공유 받아 기계 판별 가능한 항목 자동화
  - 항목별 탈락 사유 기록: 어떤 기준에서 탈락했는지 남기고 분포 확인
  - 예외(경계) 케이스 별도 표시(기준 1개만 소폭 미달한 건): '보류'로 두고 투자개발본부가 AMS에서 최종 판단
  - 분기/반기 단위로 '자동 탈락' 건을 샘플링해 기준 적절성 점검·조정
- **과거 이력 재활용**
  - 과거 수집된 매물이 다시 들어오면 과거 검토 기록(탈락 사유/메모)을 자동으로 표시

## 2단계 — 검토 (AMS = 검토 Agent)

**가설**: 투자개발본부는 투자 검토 과정에서 질문에 답을 찾는 데(자료 찾기, 유사 사례 찾기, 가정값 근거 정리, 외부 환경 반영 등) 시간·비용이 많이 든다. 이 구간을 시스템이 보조하면, 같은 인력으로 더 많은 딜을 더 빠르게 검토할 수 있다.

→ 따라서 AMS는 **검토 과정에서 반복적으로 등장하는 질문에 답해주는 시스템**을 지향.

핵심은 AMS가 무엇을 답해야 하는지(= **검토 질문 리스트**)를 투자개발본부와 함께 정리하는 것.

**예시 질문**: "1km 반경 내 경쟁 공급과 예정 공급은 임대료·OCC·ramp-up 가정에 어떤 압력을 주는가? / 이 입지의 프리미엄은 임대료·OCC·임대료 상승률 중 어떤 언더라이팅 가정에 반영해야 하는가? / 실제 계약 임대료는 최초 가정과 얼마나 달랐는가?"

추가로 외부 환경(뉴스·규제·정책·매크로)을 가치 평가에 어떻게 반영할지에 대한 질문 리스트도 보완 중.

### 검토 질문 리스트 ① — 코리빙 입지 프리미엄의 언더라이팅 반영 (35개)

**상위 질문**: 이 입지는 코리빙 개발 사업 관점에서 어떤 프리미엄/디스카운트 요인을 가지며, 그 요인은 임대료·OCC·ramp-up·임대료 상승률 같은 언더라이팅 가정에 어떤 크기와 신뢰도로 반영되어야 하는가?

**1) 입지와 수요 적합성**
1. 이 입지는 코리빙 수요 관점에서 어떤 수요 세그먼트와 가장 잘 맞는가?
2. 도보 5/10/15분 생활권 안에 어떤 수요처가 있는가?
3. 대중교통 15/30분 내 접근 가능한 업무지구·대학·병원·상권·환승거점은 무엇인가?
4. 직장인·대학생·외국인·장기체류자·1인 가구 수요 중 어떤 수요에 가장 강한가?
5. 해당 수요는 단기적인가, 안정적으로 반복되는 구조적 수요인가?

**2) 경쟁 공급과 예정 공급**
1. 반경 내 현재 경쟁 공급은 무엇인가? (원룸·오피스텔·도생·코리빙·쉐어하우스·기숙사·생숙)
2. 반경 내 예정 공급은 무엇이며, 언제 시장에 들어오는가?
3. 경쟁 공급은 이 프로젝트와 직접 경쟁하는가, 일부 수요만 겹치는가?
4. 경쟁 공급의 임대료·공실률·상품 수준·어메니티 수준은 어떠한가?
5. 주변 경쟁/예정 공급은 임대료·OCC·ramp-up·임대료 상승률 가정에 어떤 압력을 주는가?

**3) 기준 임대료와 Comparable**
1. 이 입지의 기준 임대료 comparable은 무엇인가?
2. comparable 중 실제로 코리빙 상품과 비교 가능한 사례는 무엇인가?
3. 제외해야 할 comparable은 무엇이며, 제외 사유는 무엇인가?
4. comparable의 보증금·월세·관리비·환산임대료·㎡당 임대료는 얼마인가?
5. 기준 임대료는 comparable 평균값·중앙값·상단값 중 무엇을 기준으로 삼아야 하는가?

**4) 프리미엄/디스카운트 요인**
1. 이 입지의 접근성 프리미엄은 어느 정도인가?
2. 생활편의·상권·어메니티 프리미엄은 어느 정도인가?
3. 코리빙 브랜드·커뮤니티 상품 적합성 프리미엄은 있는가?
4. 경쟁 공급 과다·소음·치안·유흥가·노후도 등 디스카운트 요인은 무엇인가?
5. 각 프리미엄/디스카운트 요인은 어떤 근거 데이터로 설명되는가?

**5) 언더라이팅 가정 반영**
1. 이 입지 프리미엄은 임대료·OCC·ramp-up·임대료 상승률 중 어떤 가정에 반영해야 하는가?
2. 프리미엄 반영값은 몇 %·몇 개월·몇 %p 수준이 적절한가?
3. 경쟁 공급 압력은 임대료 할인·OCC 하향·ramp-up 지연·임대료 상승률 하향 중 어디에 반영해야 하는가?
4. 보수/기준/상방 시나리오별 가정은 어떻게 달라져야 하는가?
5. 이 가정 변경이 Projected IRR·NOI·valuation·acquisition spread에 어떤 영향을 주는가?

**6) 근거와 신뢰도**
1. 각 가정은 어떤 근거에 의해 채택되었는가? (학술연구·시장리포트·로컬 comparable·내부 운영 실적·담당자 판단)
2. 각 근거의 신뢰도는 높음/중간/낮음 중 어디인가?
3. 시스템 추천 가정을 사람이 승인했는가, 수정했는가?
4. 사람이 수정했다면 어떤 이유로 수정했는가?
5. 최종 채택된 가정과 근거는 Valuation Case에 스냅샷으로 저장되었는가?

**7) 사후 검증과 학습**
1. 실제 계약 임대료는 최초 가정과 얼마나 달랐는가?
2. 실제 OCC와 안정화 기간은 최초 OCC/ramp-up 가정과 얼마나 달랐는가?
3. 임대료/OCC 오차의 원인은 수요 과대평가·경쟁 공급·상품력·가격 정책 중 무엇인가?
4. 이 입지 프리미엄 판단은 Tracking IRR 또는 Realized IRR에서 검증되었는가?
5. 이 케이스의 오차와 학습 결과를 다음 코리빙 Valuation Case의 기준 가정에 어떻게 반영할 것인가?

### 검토 질문 리스트 ② — 외부 환경(뉴스·규제·정책·매크로) 반영 (6개)

**상위 질문**: 외부 환경이 바뀌었을 때 투자 판단에 어떻게 반영되는가? (예: 금리/정책/규제/매크로)

1. 지금 금리/정책/뉴스 기준으로, 이 딜의 가치 평가 가정은 어떻게 조정하는 게 맞나? (근거 포함)
2. 외부 환경을 반영하면 IRR/NOI/DSCR(또는 내부 핵심 지표)가 기준 대비 얼마나 변하나? (보수/기준/상방)
3. 최근 규제/정책 변화가 인허가·운영·매각(Exit) 리스크에 주는 영향은 뭐고, 리스크 프리미엄을 어느 가정에 반영해야 하나?
4. 유사한 외부 환경(과거 고금리/경기 둔화 등)에서 유사 입지·유사 상품의 임대료/OCC는 실제로 어떻게 움직였나?
5. 외부 환경 변화로 금융비용/자금조달 가정이 바뀌면, Plan A/B/C(구조화) 우선순위도 같이 바뀌어야 하나?
6. 위 조정이 필요하다는 판단을 했을 때, "기준 변경 내역(무엇을, 왜, 얼마나 바꿨는지)"을 케이스에 어떻게 남기는 게 좋은가?

### 기능 후보 (검토 Agent)

기능 후보는 두 단계로 나눈다. **Phase 1**은 숫자가 어디서 와서 어떻게 변하는지를 시스템이 알게 만드는 데이터/계산 인프라이고, **Phase 2**는 그 위에서 검색·추천·검증이 가능해지는 레이어다.

**[Phase 1: 데이터/계산 인프라]**

- **가정값(언더라이팅) 근거/이력 관리**
  - 임대료·OCC·CAPEX·OPEX 등 핵심 가정값의 근거를 남기고, 변경 이력을 추적
  - 왜 가정값을 조정했는지 근거/메모를 함께 남김
  - 산출물(투심 자료/IR 등)에 들어간 숫자가 어떤 가정값에서 왔는지 출처 연결
  - CAPEX를 가져올 때, 어떤 상품기획안 버전을 기준으로 했는지와 언제 갱신됐는지 기록
- **Valuation(재무모델) 자동화/연동**
  - 재무모델 시스템화: 엑셀 가정값을 한 곳에 모아두고, 보수/기준/상방으로 넣으면 투자 지표들이 어떻게 변하는지 바로 표시
  - 운영 데이터(빌딩케어·DAOL·OA) → 임대료·OCC·운영비 가정에 자동 연결
  - CAPEX 금액이 바뀔 때마다 IRR/NOI/매입 스프레드/손익분기 재실률 자동 계산
- **CAPEX 입력 구조 정리**
  - 공사비를 건축/인테리어/FF&E/설계비/인허가/MEP/예비비처럼 항목별로 나눠 AMS 가치평가 입력칸에 1:1 매핑
- **입력 품질/재판단 지원**
  - 중단 사유 정형화 + 매입가능금액 필수 입력(재판단 가능하게)

**[Phase 2: 검색/추론 레이어]** (Phase 1 위에)

- **질문에 답변(검색/요약/근거 제시)**
  - 내부 자료/과거 딜/운영 데이터/시장 자료에서 관련 정보를 찾아 답변
  - 답변마다 근거(링크/출처)를 함께 표시
- **유사 사례(Comparable) 추천**
  - 조건이 비슷한 과거 케이스를 찾아 결과/차이점/리스크를 요약
- **리스크 체크리스트/시그널**
  - 자주 질문 받는 리스크 관련 질문을 자동으로 띄우고 누락 항목을 표시
- **사후 검증/학습 (환류 구조)**
  - 사후 검증: 실제 임대료/공실률/안정화 기간이 처음 가정과 얼마나 달랐는지 비교하고 차이 이유를 정리
  - 가정값 환류 메커니즘: 담당자가 가정값을 수정하면 수정 사유와 수정 전/후 값을 자동 저장
  - 분기마다 누적된 수정 이력 + 사후 검증 결과를 바탕으로 시스템이 baseline 가정값 후보를 제안 → 투자개발본부가 확인/승인 후 반영
  - 핵심: 매번 사람이 "다음 딜 기본값"을 수동 업데이트하는 게 아니라, 수정 자체가 다음 baseline을 만드는 근거가 되는 구조

## 3단계 — 조율 (조율 Agent)

**가설**: 조율 단계에서 제일 시간이 새는 지점은 투자자가 확인하고 싶은 자료가 한 번에 안 모이는 것이다. 자료가 늦게 오거나, 버전이 여러 개로 섞이거나, 담당자가 바뀌면서 설명이 끊기면 투자자는 같은 질문을 다시 할 수밖에 없고, 그만큼 내부 심의도 늦어진다.

→ 따라서 이 단계에서 필요한 역할은 "결론을 대신 써주는 것"이 아니라, **필요한 자료를 제때 모아 한 번에 볼 수 있게 정리해서 전달하는 것**이다.

이 역할을 담당하는 것이 조율 Agent이며, AMS(검토 단계)와는 성격이 달라 별도 서비스로 본다.

**예시(병목 상황)**: 투자자가 자료 요청 → 투자개발본부가 매도인/외부 기관에 요청 → 회신 지연/추가 요청 반복 → 투자자 내부 심의가 늦어짐

**서비스 원칙**: 투자자에게는 "결론"보다 원자료(파일/표) + 출처 + 핵심 포인트 정리를 주는 게 더 쓸모가 있다.

**기능 후보:**

- **자료 수집/선제 준비**
  - 금리·정책·규제 관련 기본 자료 자동 수집
  - 과거 딜/운영 데이터/시장 자료 등 내부 자료를 모아, 투자자가 궁금해할 포인트를 미리 정리해 공유
- **자료 전달/공유**
  - 자료가 들어오면 알림 → 원자료(파일/표) + 출처 + 핵심 요약까지 묶어서 바로 전달
  - CAPEX 산정 근거 패키지 제공: 상품기획안·면적표·단가표·견적 근거를 "원자료 + 출처" 형태로 투자심의 자료용으로 자동 정리
- **외부 공유 자료 관리(최신본/버전)**
  - 외부로 나가는 자료(LOI, 인허가 검토자료, 회사소개서 등)는 최신본이 헷갈리지 않게 버전/수정이력 관리
  - 외부 공유 자료를 한 곳(목록/폴더)에서 정리해 공유
- **딜 진행/관계 관리(반복 커뮤니케이션 감소)**
  - 매도인/투자자/내부 결재 일정과 증빙/서류 체크리스트를 한 화면에서 같이 관리
  - 투자자별로 요구자료/선호조건/진행 방식을 메모처럼 누적해두고 다음 딜에서 참고

## 4단계 — 구조화 (구조화 Agent)

**가설**: 딜이 빨리 진행되더라도 자금(투자자/펀드)이 같은 속도로 바로 붙지 않는 경우가 잦다. 이때 자금이 붙는 속도와 딜이 진행되는 속도 사이에 시차가 생기면, 딜 자체가 지연되거나 플랜을 바꿔야 하는 상황이 반복된다.

→ 따라서 이 단계에서는 상황에 맞는 구조화 플랜(Plan A/B/C)을 빠르게 고르고, 리스크 신호가 보이면 미리 다음 플랜으로 전환 준비를 하는 역할이 필요하다.

이 역할을 담당하는 것이 구조화 Agent이며, 목표는 "계산을 대신하는 것"보다는 플랜 선택/전환을 빠르게 하기 위한 체크·정리·리마인드에 가깝다. 최종 플랜 선택/전환 의사결정 주체는 투자개발본부.

**역할 예시**: 지금 상황에서 가능한 플랜이 무엇인지, 1순위/2순위가 무엇인지, 언제 플랜을 바꿔야 하는지(전환 신호)를 계속 보여주는 역할.

**데이터 흐름**: 구조화 Agent는 검토 Agent의 Valuation 산출물을 감지. 검토 단계에서 가정값이 바뀌어 지표가 변동하면, 그 변동이 자동으로 'Plan A 흔들림 신호'를 발생.

**기능 후보:**

- **플랜 후보/우선순위 정리**
  - 현재 상황에서 가능한 Plan A/B/C를 정리하고 1순위·2순위를 제안
  - 상황이 바뀌면(금융/규제/매도인 일정 등) 플랜 우선순위를 자동으로 재정리
- **플랜 전환 신호 조기 감지**
  - Plan A가 흔들리는 신호(리스크 상승)를 먼저 감지해서 알림(전환이 늦어져서 딜이 꼬이는 것 방지)
  - 각 플랜이 어떤 조건에서 안 되는지(막히는 지점)를 정리해두고, 해당 조건이 발생하면 바로 표시
  - 내부 요인도 감지: 외부 변수(금리/규제)뿐 아니라, CAPEX 증가 → IRR 하락 → 투자자 매력도 하락처럼 우리 쪽 숫자 변화도 'Plan A 흔들림 신호'로 자동 감지해 다음 플랜 트리거
- **플랜별 실행 준비(체크리스트/서류)**
  - 플랜별로 필요한 서류·절차·담당자·마감일을 체크리스트로 관리
  - 진행 단계 체크 + 다음 액션 리마인드/알림
- **시뮬레이션/비교(필요 시)**
  - 특정 상황에서 Plan A/B/C를 적용했을 때 결과(시간/비용/리스크)를 비교
  - 플랜 전환 시 "지금 바꾸면 드는 비용 vs 조금 더 기다리면 드는 비용"도 비교

**요청**: 해당 agent 구현이 필요할 경우, 투자개발본부의 plan 수립 logic 정리부터 시작해야 함 — 정리된 로직과 실제 사례 필요.
